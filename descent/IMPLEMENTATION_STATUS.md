# DESCENT implementation status

Last validated: 2026-09-03
Godot: 4.7.2.stable
Current milestone: full port from the C++ GDExtension to GDScript and scenes.

## The port

The game was previously a native C++ GDExtension that drew the entire world and
HUD procedurally onto a canvas from `descent_draw.cpp`. Nothing was editable in
the Godot editor. That is now gone: every actor, prop, effect, and UI element is
a scene you can open and edit.

Removed:

- `descent/src/`, `descent/include/` — all C++ sources and headers
- `descent/gdextension/` — the extension manifest
- `descent/bin/` — compiled libraries
- `SConstruct`, `GODOT_CPP_REVISION`, `.sconsign.dblite` — the SCons build
- `godot-cpp/` — the bindings submodule

Added: 60 GDScript files and 46 scenes. See
[ARCHITECTURE.md](../ARCHITECTURE.md) for the map.

## Completed

- **Three top-level scenes.** `boot.tscn` warms the resource cache and routes on;
  `main_menu.tscn` starts runs and spends echoes; `gameplay.tscn` holds the run
  loop.
- **Four autoloads.** `SaveManager` (persistent progression, atomic disk writes,
  validated loads), `RunState` (per-run state), `EventBus` (presentation-only
  signals), `SceneRouter` (the only scene swapper, with fade).
- **Player as a scene.** `CharacterBody2D` with health, mana, hit-flash, input,
  and melee-hitbox components; three cooldown timers; a dash trail; and an
  `AnimationPlayer` for idle and walk. The sword cone is a `CollisionPolygon2D`
  tunable by dragging points.
- **Four enemy scenes** sharing `EnemyBase`, each with its own idle animation and
  `_steer()` implementation. Enemies request shots, summons, and hazards by
  signal; the controller decides what those mean.
- **Fifty level scenes**, one per painted map in `descent/assets/maps/`, each
  marked flat or vertical, with hazard zones, platforms, death zones, walkable
  bounds, spawn markers, the player start, and door anchors authored as nodes.
  Generated by `tools/gen_levels.py` and reviewed by hand.
- **Full UI set:** HUD with chip-lag stat bars and a boss bar, six-slot hotbar
  with cooldown sweeps, upgrade cards, merchant panel, pause menu, run summary,
  permanent-upgrade shop, toasts, door prompt, and twin touch sticks.
- **Effects layer:** impact bursts, floating damage numbers, camera shake, hit
  stop, the fall-shaft floor transition, and the room banner — all driven off
  `EventBus`, capped at 90 live effect nodes.
- **Data-driven catalogs.** Upgrades, shop offers, and per-floor difficulty load
  from `descent/data/` at runtime, so adding a `.tres` registers it.
- **Roguelite loop intact:** eight floors, three-door choice, loot rooms with
  three-card rewards, merchant vaults, danger rooms with three modifiers, the
  Warden's two-phase boss fight, Second Wind revives, and echo banking.

## Validation

All run against Godot 4.7.2 headless.

### 1. Project import

```bash
godot --headless --path . --import --quit
```

Result: PASS. No parse errors, no missing resources, no warnings.

### 2. Headless scene runs

```bash
godot --headless --path . --quit-after 500 res://descent/scenes/boot.tscn
godot --headless --path . --quit-after 400 res://descent/scenes/gameplay.tscn
```

Result: PASS. Clean output, exit code 0.

### 3. Run-loop flow test

A temporary harness drove the state machine end to end. All assertions passed:

- floor 1 reaches combat, clears, and opens doors
- the loot door advances the floor and the loot room offers three upgrades
- installing an upgrade records the stack and leads to doors
- the shop room opens with doors already unlocked; all three offers purchase
- the danger room rolls a modifier and counts toward the clear tally
- pause and resume toggle the tree
- floor 8 spawns exactly one boss; its death finishes the run as a victory
- Second Wind revives once, and the next death ends the run as a defeat

## Incomplete or deferred

- Audio: no sound effects or music yet. `descent/assets/concept_audio.wav` is a
  reference track only.
- Haptics are limited to `Input.vibrate_handheld()` on player damage.
- Android runtime validation on an emulator or device is still pending.
- The flow-test harness was removed after use; there is no committed automated
  test suite.
